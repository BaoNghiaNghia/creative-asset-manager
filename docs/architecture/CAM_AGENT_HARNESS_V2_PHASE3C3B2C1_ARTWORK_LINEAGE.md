# CAM Agent Harness Phase 3C.3B2C1 — Verified artwork lineage preflight

Date: 2026-11-09. Base production: `f24310504`. Schema stays `0205_cam_agent_trial_evidence`, no migration.

## Why this split is mandatory

The deployed Agent Harness has credible Creative Brief **text-treatment** receipts for baseline/challenger (default OFF). A Stage 1 PNG is produced by a **separate** image-generation ProcessingJob, so treating a Creative Brief exposure as evidence that a particular PNG was generated by that policy would be unjustified. The existing `cam_agent_trial_qa_reviews` references output-version rows with restrictive FKs, while Stage 1 Regenerate may delete old remote files/versions. Direct QA writes before establishing durable reviewed-artifact retention can break existing Regenerate, delete, and product-selection workflows.

This phase deliberately **does not write QA rows**. It adds the missing independent provenance and byte-integrity preflight only.

## Release behavior

1. `GET /api/v1/admin/agent-harness/{tenant_id}/trials/stage1/{study_id}/artwork/{output_version_id}/lineage`:
   - Requires BOTH `ai_operations.read` and `ai_provider.configure`, the normal Agent Harness read flag, and tenant scope.
   - Validates current tenant study/assignment, **exposed** control/challenger receipt and correct policy version, completed Creative Brief and its completed ProcessingJob, and the completed Stage 1 image ProcessingJob. All must be from the same tenant/keyword and point to the current image generation attempt.
   - Verifies the immutable image job's pinned `creative_v3` source/keyword/fingerprint against the actual output version's `font_info_json`; independently recomputes the source hash of the currently stored validated Creative Brief. Any changed/regenerated source that cannot be verified fails closed.
   - Requires server-uploaded SHA-256 metadata, technical-qa upload pass, PNG type and bounded size/dimensions. Returns only safe lineage/verification state, never arm, keyword, prompt, reviewer identity or raw artwork.
   - This is **database-linked**, not independent remote-file byte verification; output remains ineligible for A/B evaluation.

2. `POST /api/v1/admin/agent-harness/{tenant_id}/trials/stage1/{study_id}/artwork/{output_version_id}/verify-bytes`:
   - In addition to the same permissions/tenant, requires `AGENT_HARNESS_TRIAL_ARTWORK_VERIFY_ENABLED=true` (default **OFF**), active registration flag and emergency stop OFF.
   - Rechecks lineage before read, streams actual Google Drive managed-storage bytes with a **16 MiB cap**, validates length, SHA-256, PNG signature/CRC and decoded dimensions using Pillow, closes streams on all outcomes, and rejects stale lineage rechecked after I/O.
   - This may create **Google Drive bandwidth and request load** only when an authorized caller explicitly invokes it. No AI provider, prompt, asset update or review job is invoked.
   - Returns verified storage integrity but still `independent_qa_verified=false`, `eligible_for_a_b_evaluation=false`. The temporary result is not persisted as independent QA evidence.

## Safety/compatibility limitations

- Current-pinned outputs only: older regenerated image attempts and Creative Brief revisions whose original immutable content no longer exists are rejected; no inference or replay from historical Pick/Reject.
- Existing metadata (`content_sha256`) is **expected** checksum until remote bytes have been streamed. Verified PNG encoding does not verify readability, spelling, cap fit, originality, human judgement or cost.
- This phase does not add a blind reviewer, a new permission role, reviewer token, QA write endpoint, provider cost meter or an A/B promotion decision. **All remains blocked.**
- Do not activate challenger, control capture or QA automatically. No output deletion/retention, background backfill or new provider keys. No DB migrations and no change to existing Stage 0–2 workers.
- QA decision rows cannot safely be written until an immutable reviewed-image snapshot or retention policy is implemented that protects Stage 1 Regenerate and preserves output lineage; output-role authorization and independently authenticated reviewer IDs must be separate from generation/feedback actors.

## Rollout

Deploy `main` backend with `--no-migrate` and both control/challenger/artwork-verify feature flags unchanged (OFF). Verify production 0205 DB startup compatibility, all nine managed services, correct current/previous release and cleanup. Then implement reviewed 3C.3B2C2 immutable reviewed-artifact retention, blinded QA authorization and trusted cost telemetry under a separate deployment.
